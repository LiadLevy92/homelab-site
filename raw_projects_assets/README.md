# raw_projects_assets — חומרי גלם של פרויקטים (פרטי)

> ⚠️ **התיקייה הזו לא מתפרסמת לאתר.** היא יושבת מחוץ ל-`public/`, ושום קובץ כאן
> לא נכנס ל-`dist/` (Astro מעתיק רק את `public/` + נכסים שמיובאים בקוד).
> כאן בטוח לשים מסמכים אישיים — ספרי פרויקט, PDFים, מצגות, תמונות גולמיות.

## מבנה
```
raw_projects_assets/
├── software_ai/
├── maker_hardware/
├── electrical_eng/
└── homelab_infra/
    └── <project-name>/
        ├── raw_docs/   ← Word / PDF / PPTX גולמי (קלוד קורא, לא מתפרסם)
        └── images/     ← תמונות גולמיות לפני אופטימיזציה
```

## ה-Workflow (מקצה לקצה)
1. **אתה:** יוצר תיקיית פרויקט תחת הקטגוריה המתאימה, וזורק לתוכה חומרים
   (`raw_docs/` למסמכים, `images/` לתמונות).
2. **אתה:** אומר לקלוד בשיחה — "עיבדתי פרויקט X" (ומציין באיזו קטגוריה).
3. **קלוד:**
   - קורא את המסמכים ב-`raw_docs/` ומחלץ סיכום מנהלים (2 שורות) + TL;DR למודל.
   - בוחר את התמונה/ות הטובות, מאפטם אותן, ומעתיק **רק אותן** אל
     `public/assets/projects/<category>/<project>/images/`.
   - מוסיף/מעדכן אובייקט פרויקט ב-`src/data/projects.ts` (כולל `state`, `linkType`, tags).
   - אם זה פרויקט "גדול" (`linkType: 'internal'`) — בונה דף פנימי; אם "נקודתי"
     (`linkType: 'modal'`) — מספיק להזין נתונים והמודל נבנה אוטומטית.
4. **קלוד:** מריץ `npm run build` לוודא שאין שגיאות, ואז push.

## חשוב
- **לעולם לא** לשים קבצים אישיים/רגישים תחת `public/`.
- תמונות לאתר: עדיף ≤ ~1600px רוחב, JP/WebP, דחוסות.
- כלל האבטחה של האתר חל גם כאן: בלי IP/שמות משתמש/סיסמאות בתוכן המתפרסם.
